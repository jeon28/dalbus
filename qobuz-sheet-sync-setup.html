QOBUZ 시트 연동 설정

QOBUZ 계정 DB를 구글 시트로 자동 미러링하려면 구글 서비스 계정이 필요합니다. 이 문서는 GCP 콘솔에서 계정을 만들고 키를 발급받아 앱에 연결하기까지의 전 과정입니다. 코드는 이미 배포돼 있고, 환경변수가 채워지는 순간 동작합니다.

소요 시간
약 15분
필요 권한
GCP 프로젝트 편집자
비용
무료
설정 전 상태
앱 정상 동작

시작하기 전에

서비스 계정은 사람이 아닌 프로그램용 구글 계정입니다. 고유한 이메일 주소를 가지고, 비밀번호 대신 비밀키로 인증합니다. 달버스 서버가 이 계정 자격으로 시트에 접근하게 됩니다.

그래서 순서가 중요합니다. 계정을 먼저 만들고, 그 계정의 이메일 주소를 알아낸 다음, 사람에게 시트를 공유하듯 그 주소에 시트를 공유합니다. 이 공유 단계를 빠뜨리는 것이 가장 흔한 실패 원인입니다.

설정 전에도 앱은 정상입니다

환경변수가 없으면 동기화 코드가 조용히 건너뜁니다. 중간에 멈추셔도 관리 화면과 계정 배정은 아무 영향을 받지 않습니다.

설정 절차

  1. Google Sheets API 활성화

    console.cloud.google.com

    1. GCP 콘솔에 접속해 프로젝트를 선택합니다. 없으면 새로 만듭니다 (이름은 dalbus 정도면 충분합니다).
    2. 상단 검색창에 Google Sheets API를 입력해 이동합니다.
    3. 사용 설정(Enable) 버튼을 누릅니다.
    주의

    프로젝트를 여러 개 쓰고 계시면 지금 선택한 프로젝트를 기억해 두세요. 다음 단계의 서비스 계정을 같은 프로젝트에 만들어야 합니다. API는 프로젝트 단위로 켜지기 때문에, 다른 프로젝트에 계정을 만들면 인증은 되는데 API 호출이 거부됩니다.

  2. 서비스 계정 만들기

    IAM 및 관리자 › 서비스 계정

    1. 왼쪽 메뉴에서 IAM 및 관리자 › 서비스 계정으로 이동합니다.
    2. 서비스 계정 만들기를 누릅니다.
    3. 이름에 dalbus-sheet-sync를 입력합니다. 계정 ID는 자동으로 채워집니다.
    4. 만들고 계속하기를 누릅니다.
    5. 역할(Role) 부여 단계는 건너뜁니다. 아무것도 선택하지 않고 계속을 누르세요.
    6. 마지막 단계도 비워둔 채 완료를 누릅니다.
    역할을 왜 안 주나

    GCP 역할은 클라우드 리소스 접근을 다룹니다. 시트 접근 권한은 GCP가 아니라 시트 자체의 공유 설정으로 정해집니다(4단계). 여기서 역할을 주면 필요 없는 권한만 열리게 됩니다.

  3. JSON 키 발급

    서비스 계정 › 키 › 키 추가

    1. 방금 만든 서비스 계정을 클릭합니다.
    2. 키 탭 › 키 추가 › 새 키 만들기.
    3. 형식은 JSON을 선택하고 만들기를 누릅니다. 파일이 자동으로 다운로드됩니다.

    받은 파일을 열면 이런 모양입니다. 표시된 두 값을 5단계에서 씁니다.

    다운로드된 JSON 키 
    {
  "type": "service_account",
  "project_id": "dalbus-xxxxxx",
  "private_key_id": "a1b2c3...",
  "private_key": "-----BEGIN PRIVATE KEY-----\nMIIEvQIBADAN...\n-----END PRIVATE KEY-----\n",
  "client_email": "dalbus-sheet-sync@dalbus-xxxxxx.iam.gserviceaccount.com",
  ...
}
    이 파일은 비밀번호입니다

    이 키 하나로 서비스 계정에 공유된 모든 시트를 읽고 쓸 수 있습니다. 깃에 커밋하거나 메신저로 보내지 마세요. 환경변수에 옮긴 뒤에는 다운로드 폴더에서 삭제하시는 편이 안전합니다.

    유출됐다면 GCP 콘솔의 같은 키 탭에서 해당 키를 삭제하고 새로 발급하면 됩니다.

  4. 시트를 서비스 계정에 공유

    QOBUZ 스프레드시트 › 공유

    1. JSON 파일의 client_email 값을 복사합니다. ...@....iam.gserviceaccount.com 형태입니다.
    2. QOBUZ 스프레드시트를 열고 우측 상단 공유를 누릅니다.
    3. 그 이메일 주소를 붙여넣고 권한을 편집자로 지정합니다.
    4. 알림 보내기 체크는 해제합니다. 받는 사람이 프로그램이라 메일이 반송됩니다.
    5. 공유를 누릅니다.
    뷰어가 아니라 편집자

    앱이 시트에 쓰기 때문에 편집자 권한이 필요합니다. 뷰어로 주면 인증은 통과하는데 쓰기 시점에 403으로 실패합니다.

  5. 환경변수 설정

    .env.local  +  Vercel 대시보드

    프로젝트 루트의 .env.local에 아래 네 줄을 추가합니다.

    .env.local 
    # 3단계 JSON 의 client_email
GOOGLE_SERVICE_ACCOUNT_EMAIL=dalbus-sheet-sync@dalbus-xxxxxx.iam.gserviceaccount.com

# 3단계 JSON 의 private_key — 큰따옴표째 그대로 붙여넣기
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQIBADAN...\n-----END PRIVATE KEY-----\n"

# 시트 URL 의 /d/ 와 /edit 사이 문자열
QOBUZ_SHEET_ID=1TsyiyXzWNcDLbGSmIYK4Qi5HZDNQEmepnWbgRMBKh2s

# 야간 자동 백업 보호용 — 아무 긴 랜덤 문자열
CRON_SECRET=
    GOOGLE_PRIVATE_KEY 붙여넣는 법

    JSON 파일에 있는 "-----BEGIN...\n...-----END PRIVATE KEY-----\n" 값을 큰따옴표를 포함해 통째로 복사해 붙여넣으세요. 줄바꿈을 실제 엔터로 바꾸지 마세요. 코드가 리터럴 \n을 실제 개행으로 되돌립니다.

    CRON_SECRET은 야간 백업 엔드포인트를 아무나 호출하지 못하게 막는 값입니다. 아래 명령으로 만들어 쓰시면 됩니다.

    랜덤 문자열 생성 
    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

    Vercel에도 같은 네 개를 등록합니다. 프로젝트 › Settings › Environment Variables에서 Production·Preview·Development 모두에 추가한 뒤 재배포해야 반영됩니다.

    선택 사항

    기록될 탭 이름은 기본값이 QOBUZ_백업입니다. 바꾸시려면 QOBUZ_SHEET_TAB을 추가하세요. 원본 QOBUZ 탭 이름과 절대 같으면 안 됩니다. 원본이 통째로 덮어써집니다.

  6. 동작 확인

    터미널

    개발 서버를 재시작한 뒤 백업 엔드포인트를 직접 호출합니다.

    확인 명령 
    curl http://localhost:3000/api/cron/qobuz-sheet-backup

    성공하면 기록된 행 수가 돌아옵니다.

    성공 응답 
    {"ok":true,"rows":128}

    시트를 열어보면 QOBUZ_백업 탭이 새로 생겨 있고, 원본 QOBUZ 탭과 같은 A~K 열 순서로 데이터가 들어가 있습니다. 그 뒤로는 관리 화면에서 계정을 배정하거나 수정할 때마다 자동으로 다시 기록됩니다.

    아직 설정이 안 된 경우

    {"ok":false,"skipped":"구글 시트 환경변수 미설정 — 동기화 건너뜀"}이 나오면 환경변수 네 개 중 하나가 비어 있거나 서버를 재시작하지 않은 것입니다.

문제 해결

실패하면 응답의 error 값에 원인이 그대로 나옵니다.

응답에 나오는 말 원인과 해결
Sheets API 403 … The caller does not have permission 4단계 공유 누락. 서비스 계정 이메일에 시트를 편집자로 공유했는지 확인하세요. 뷰어로 돼 있어도 이 오류가 납니다.
Sheets API 404 … Requested entity was not found QOBUZ_SHEET_ID 오타. 시트 URL의 /d/와 /edit 사이 문자열만 넣어야 합니다. URL 전체를 넣으면 이 오류가 납니다.
Google Sheets API has not been used in project … before or it is disabled 1단계 누락, 또는 프로젝트 불일치. 메시지에 나온 프로젝트 번호가 서비스 계정을 만든 프로젝트와 같은지 확인하세요.
invalid_grant 또는 DECODER routines::unsupported 비밀키 형식 문제. GOOGLE_PRIVATE_KEY가 큰따옴표로 감싸여 있는지, \n이 실제 엔터로 바뀌지 않았는지 확인하세요.
{"error":"Unauthorized"} · HTTP 401 CRON_SECRET 불일치. 값을 설정했다면 호출할 때 Authorization: Bearer <값> 헤더가 필요합니다. Vercel Cron은 자동으로 붙입니다.
응답은 ok:true인데 시트가 그대로 다른 시트를 보고 계실 가능성. QOBUZ_SHEET_ID가 가리키는 시트와 열어둔 시트가 같은지, QOBUZ_백업 탭이 아래쪽에 새로 생기지 않았는지 확인하세요.

설정 후 알아둘 것

  • ›
    시트는 보기 전용 사본입니다. 원장은 DB이고, 시트에서 고친 값은 다음 동기화 때 조용히 덮어써집니다. 팀에 이 점을 알리거나, 해당 탭에 보호범위를 걸어 편집을 막아두시는 편이 안전합니다.
  • ›
    원본 QOBUZ 탭은 건드리지 않습니다. 앱은 QOBUZ_백업 탭에만 씁니다. 탭 이름을 바꾸실 때만 주의하시면 됩니다.
  • ›
    기록 시점은 두 가지입니다. 관리 화면에서 쓰기 작업(배정·수정·삭제·이동·활성 토글)을 할 때마다 즉시, 그리고 매일 새벽 3시(KST)에 전체 스냅샷이 한 번 더 돕니다. 마이그레이션이나 수동 SQL처럼 앱을 거치지 않은 변경은 이 야간 작업이 메웁니다.
  • ›
    시트 장애가 관리 업무를 막지 않습니다. 동기화는 응답을 보낸 뒤에 실행되고, 실패해도 예외를 던지지 않습니다. 구글 쪽이 죽어도 계정 배정은 정상 처리되고 실패는 서버 로그에만 남습니다.
  • ›
    삭제된 배정은 시트에 안 나옵니다. 활성·비활성 슬롯만 기록되고 상태 열로 구분됩니다. 삭제 내역은 관리 화면의 삭제 내역 페이지에서 확인하고 복구할 수 있습니다.
